## Code-path decision

1. OperationsSetupService initializes the real form/installation context.
2. BindingRepairService maps authoritative Gravity Forms fields through immutable CAS-activated binding versions.
3. InboxSetupService adopts the globally shared Inbox visual profile and reuses each form-specific binding context; InboxRuntimeReadinessService qualifies source configuration and host seams, recording PROVEN or NOT_PROVEN source-bound availability evidence.
4. InboxPresentationModel resolves exact form/entry/binding context, evidence hash, immutable version, semantic slot and source. It does not verify actual nonempty entry values. The source being configured and a particular entry having complete data are separate conditions.
5. InboxPresentationAdapter uses the active global profile and available active binding-set snapshots to construct the model. It does NOT call presentationReadiness(entry) from the row rendering path, and never owns host rows/query/permission. An authentic frontend shortcode/native Block gets GPP framing around the host render; wp-admin remains host-owned. An absent profile/model/route leaves native markup.
6. Separately, Bootstrap registers InboxTableHeaderPresentation through Gravity Flow's official gravityflow_columns_inbox_table and gravityflow_inbox_field_value seams. That adapter DOES consume per-form source-bound availability evidence (the exact binding/source/version ref) to admit a table-wide five-column projection and plain-text First+Last / School+Grade display. It requires Gravity Flow's authoritative form_id in the column-hook args, valid PROVEN fields and entry.created_at, unique native field identities and unchanged host date display companion. If context is unscoped/ambiguous, proof is missing/stale or a different form is selected, it returns native columns/values instead. It reads actual entry values only to compose bounded plain text, never to hide entries or authorize requests; missing entry values stay missing rather than guessed.
7. Runtime diagnostics distinguish global activation and source readiness; no GPP readiness bit confers request authorization.

Thus the prior all-or-nothing Card Mode fallback no longer applies. An incomplete/unproven form's real Gravity Flow-assigned entry must not disappear because GPP cannot resolve its semantic data. Table-wide five-column native-filter projection is scoped to a proven, unambiguous form; an unscoped multi-form query deliberately keeps default native columns. The global shell may be admitted even when a particular entry's semantic readiness is false; that entry receives no unsupported GPP-specific field enrichment. No missing mapping is guessed.

## Initial falsification and repair of the acceptance instrument

Earlier Blocksy attempts correctly rejected two mistaken test assumptions: all Inbox routes have five columns (unscoped host returns five configured native definitions; visible header nodes may be virtualized to fewer), and five host-defined columns must always mean five currently materialized DOM headers (AG Grid column virtualization renders a subset). The instrument now distinguishes host-emitted Grid configuration from visible DOM nodes, with the original source-bound five-column projection required only on qualified form-scoped routes. Both are read-only test changes, not a waiver of the authoritative production contract. Authentic navigation and native fallback still require separately executed exact-Head proof.
